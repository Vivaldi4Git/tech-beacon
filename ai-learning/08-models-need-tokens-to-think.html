# 推理的本质：有限计算

我们知道，模型在回答问题时，其实是在做推理（inference）。推理本质上是通过一个大型数学表达式预测下一个 token 的概率分布，而这个表达式的计算次数是有限的。这意味着单次预测只能做有限的计算。

这里的“token”，可以简单理解为模型处理的最小文本单位，可能是一个字、一个词，或者一串字符。

要让模型处理复杂问题，必须把计算量拆分成多个预测，像流水线一样拼接起来。

比如你问：“1+1+1+1=？” 如果让模型直接输出“4”，它需要在一个 token 内完成所有计算，容易出错。

这就像让你“一口气”说出复杂问题的答案，不能写草稿、不能分步演算，容易出错。
比如直接问“1+1+1+1=？”，要求它直接输出“4”，那么模型必须在生成“4”这个 token 的那一次前向传播（即模型每次计算输出的过程）里，把所有推理和计算都做完。

如果让模型一步步写：“1+1=2，2+1=3，3+1=4”，每步都很简单，模型更容易做对。当然模型的计算能力没那么差，这里只是举例。

# 复杂问题的分步推理

你可以试试下面这个问题：

Emily buys 23 apples and 177 oranges. Each orange costs $4. The total cost of all the fruit is $869. What is the cost of each apple?
Answer the question in a single token. i.e. immediately just give me
the answer and nothing else.

然后告诉 chatgpt 可以用更多 token：

Ok now work out the problem normally, you can use as many tokens
as you like.

# 用代码辅助推理

Karpathy 提出了一个实用方法：因为模型的“心算”结果不可靠，可以让模型用代码解题（use code）。
当你让模型“use code”，它会生成一段代码（如 Python），由外部真实代码环境运行，最后把结果返回。
